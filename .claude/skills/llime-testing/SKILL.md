# Testing in llime

## Overview

Every non-trivial rule gets a small test that fails if the rule breaks. Tests use the shared core's types and vocabulary, so a test can never drift from the product. Evidence for a handoff is the actual output of the commands below.

## Where tests go

| Kind | Path | Runs in |
|---|---|---|
| Pure rules (search, decision, assessment, state machine, teacher analysis) | `tests/<module>.test.ts` | `npm test` |
| Store and transactions (real Neo4j) | `tests/store.<topic>.test.ts` | `npm test` |
| Shared builders | `tests/builders.ts` | imported by tests |
| Browser (Playwright + axe-core) | `tests/e2e/<flow>.spec.ts` | `npm run test:e2e` |
| Live Codex or GPT-Live | `tests/runtime/<name>.test.ts` | `npm run live:<name>` only, never `npm test` |

Never put tests under `src/` or `web/`.

## Commands

```text
npx tsx --test tests/search.test.ts   # one file while working
npm run typecheck                     # both projects: server and web
npm test                              # the whole unit suite, seconds
npm run test:e2e                      # browser checks
npm run live:<name>                   # only on a computer with keys: Mac Studio or Sunho's Mac
```

## Rules

- **Red first.** Write the test, run it, see it fail for the right reason, then implement.
- **Boundaries at the exact value.** Test a threshold at the value and just past it, for example `0.6` admitted and `0.59` rejected.
- **Mutation check before handoff.** Change one constant in the rule (for example `0.12` → `0.13`), confirm a test fails, revert.
- **Types and values come from the shared core.** Import types (`z.infer`) and vocabulary from `src/domain.ts`. Use real strategy and outcome values (`make_ten`, `independent`). Never declare `type Outcome = ...` or invent values like `'s1'` in a test.
- **Builders, not giant fixtures.** Add small builders to `tests/builders.ts` (for example `rankedCase({score, coverage, strategy, outcome})`) with sensible defaults; each test sets only what it needs.
- **Fixtures go through the schemas.** Seed, captures and Storybook fixtures are parsed by the shared zod schemas in a test. A derived fixture is generated by a script, never typed by hand.
- **Store tests use the real local Neo4j.** Give each test file its own run namespace (`test-<file>-<pid>`) and delete it in `after`. Assert on committed records, the emitted event and the idempotency receipt; retry once and assert nothing duplicated.
- **Mock only what costs money or is outside our control.** That means Codex and GPT-Live, and the test name says so: `chooses make_ten from a recorded interpretation (mocked Codex)`.
- **Deterministic.** Inject the clock (`now`) and seeds. No `sleep`, no network, no dependence on test order.
- **Name the rule.** `rejects a case with coverage below 0.6`, not `admit works`.
- **Test behavior.** Assert on outputs, committed records and events. A test that only checks a schema has a key is not a test.

## Unknown API

If the module you test does not exist yet or its names are unclear (for example the store API), do not guess names. Ask the coordinator at check-in ③ and write the pure-rule tests meanwhile.

## Handoff evidence

Paste, in this order:
1. `npm run typecheck` output.
2. `npm test` output with the pass count.
3. The mutation check: what you changed and the failing test name.
4. Any `test:e2e` or `live:*` output your Task needed.

Say plainly what you ran and what you only read.
